# QA: рабочий график и будильники (0.5)

## Автотесты (включены в Actions при каждом коммите)
Запуск `gradle :app:testDebugUnitTest`, затем `gradle :app:assembleDebug`.
`ShiftRulesTest`: расчёт индекса цикла, смена месяца, пауза без сдвига, выключенный график, рабочий/выходной, настройки типа и графика, переопределение только одной даты, несколько временных замен, отмена сигнала, будильник накануне, источники времени.

## Проверить вручную на реальном Android
1. **Рингтон.** Настройки → звук → выбрать нестандартную системную мелодию, выключить/включить вибрацию; проверить, что применяется именно она, а не общий звук уведомлений.
2. **Тестовый звонок.** Дождаться срабатывания при разблокированном и заблокированном экране; «Отключить» должен остановить звук и открыть главную без старого всплывающего окна. «Отложить на 5 минут» должно сработать даже после перехода в главную.
3. **Звук в фоне.** Экран погашен, приложение выгружено из недавних. Проверить на HyperOS отдельно при ограничениях фоновой работы; не полагаться только на эмулятор.
4. **Наследование.** Два одинаковых типа «Рабочий» в одном цикле, общий сигнал 06:30 из типа; изменить время в типе — обе будущие смены обновятся. Личная правка на одной дате не меняет другую.
5. **Отсутствие сигнала.** В рабочем дне специально отключить его: интерфейс обязан объяснить причину. Для выходного сигнал не должен назначаться.
6. **Смещения.** Выбрать три будущих дня, нажать «Быстро заменить тип дня» → «Выходной». По окончании трёх дней основной цикл должен продолжиться без сдвига. Кнопка «Вернуть смену из цикла» восстанавливает обычный тип.
7. **Новые типы.** При создании графика → создать тип «Подработка», задать цвет, иконку, часы и будильник, выбрать его для новой ячейки.
8. **Текст.** При вводе нового имени первая буква должна предлагаться заглавной, автозамена зависит от настроек клавиатуры на устройстве.
9. **Обновление.** Сохранить JSON через настройки, проверить файл, попробовать `adb install -r` для **того же сертификата**; при другом сертификате ожидать ошибку INSTALL_FAILED_UPDATE_INCOMPATIBLE.
10. **Разные разрешения.** Отказать в POST_NOTIFICATIONS, SCHEDULE_EXACT_ALARM и FSI по отдельности; приложение должно объяснить последствия и не запускать небезопасный тест.
11. **Разные экраны.** 360dp, 412dp, большой шрифт 1.3×, landscape; редакторы, кнопки и нижняя навигация без перекрытий.
12. **Перезагрузка, дата и часовой пояс.** Проверить восстановление будущих сигналов, переход месяца и случай с будильником накануне смены.

## UI smoke workflow
Через Actions → **UI smoke test on Android emulator** → Run workflow запускаются Android API 29 и API 35; артефакты содержат скриншоты 360×800/412×915 и logcat. Это проверяет запуск и изображения, **не** работу реальных будильников на прошивках производителей. Требует ручного анализа скриншотов.

## Риски перед RuStore
Стабильный ключ подписи; отдельная release-сборка; выбор окончательного applicationId; резервное копирование; декларации точных будильников и foreground service; реальные испытания минимум на двух моделях.

### Запуск проверки экранов (первая серия)
Сценарий запускается по обновлению этого QA-чеклиста и создаёт артефакты с реальными скриншотами эмулятора. После серии автоматический триггер будет выключен, ручной останется.
